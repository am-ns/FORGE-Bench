# FORGE-Bench：面向工业视频生成的工厂场景推理与生成评测


## 摘要

近期的图生视频模型已经能够生成视觉效果出色的视频片段，但视觉观感本身并不能可靠地说明一段工业视频是否符合物理规律、结构是否稳定、因果关系是否正确，或者能否在实际工作中使用。本文提出 FORGE-Bench——一个用于在明确的几何、物理、时间、语义和应用约束下评估工业视频生成能力的基准。

本基准包含 500 个图像条件任务，覆盖五个工业领域中的 60 个场景族，在五个领域间保持均衡，并划分为简单、中等、困难和对抗四个难度等级。我们将评估组织为正交的“领域—任务”矩阵，并考察五个技术维度：工业逻辑与事实一致性、几何完整性、物理合理性、时间一致性，以及参考图像与运动保真度；此外还单独评估工业应用实用性。

评测协议将多模态模型裁判与任务感知的计算机视觉证据相结合，同时使用明确的事件完成检查、确定性帧采样和可审计的硬性门控。我们在冻结的生成和评分协议下评估十个具有代表性的视频生成系统。

我们的分析旨在揭示传统感知质量平均分容易掩盖的失败模式，包括用静止视频替代要求的运动、拓扑结构漂移、安全响应链不完整、不合理的载荷路径，以及本应局部变化的缺陷导致全局场景重生成。我们公开代码、提示词、标注和评测产物，以支持可复现的可靠工业视频生成研究。

## 1. 引言

视频生成技术已经从只能生成短小且控制能力有限的视频，发展到能够维持主体可识别性、遵循镜头指令并渲染复杂运动的系统。现有基准通过将视觉质量分解为可解释的维度、衡量广泛的用户感知质量以及测试组合式提示词遵循能力，在推动技术发展方面发挥了重要作用。然而，这些评估仍不能完整描述工业视频的要求。

在工业场景中，一段视频即使画面清晰、时间连续，也可能在功能上完全错误。例如，起重机钢缆可能与吊物融合；挖掘机连杆可能改变拓扑结构；机器人可能穿透工件；烟雾可能逆着预期压力或气流方向扩散；安全警报也可能在没有触发事件的情况下凭空出现。这些错误不只是美观问题，它们可能使合成数据失效、产生误导性的训练材料，或者在检查和作业规划中掩盖危险。

因此，工业视频评估必须回答四类问题：发生了什么变化、哪些部分应该保持不变、事件为什么发生，以及生成的视频是否能够支持某项具体的应用决策。

为填补这一空白，我们提出 FORGE-Bench，即“面向工厂场景的推理与生成评测”。该基准从两个互相正交的角度组织任务。

第一个角度是工业场景领域：

- 视觉安全；
- 具身机器人；
- 重载施工；
- 精密缺陷生成；
- 极端应急事件。

第二个角度是被测试的抽象能力：

- 刚体运动学与耦合；
- 拓扑变化与失效；
- 流体动力学与热力学；
- 空间探索与视角运动；
- 工业逻辑与合规性。

这一“领域—任务”矩阵可以把由视觉环境造成的失败与由底层生成能力不足造成的失败区分开来。

每个任务以一张参考图像和一条可执行的图生视频提示词开始。标注中明确指定所需事件、镜头行为、最终状态、应保持不变的区域、硬约束、应用目标以及已知的误导性失败模式。

评分采用“五加一”结构：五个技术维度共同构成任务条件化技术分，工业应用实用性则作为独立维度报告并参与最终排名。任务感知的视觉算子向多模态裁判提供结构化证据，而不是不透明地替代裁判；所有硬性调整也都会在输出中明确记录。

本文的主要贡献如下：

1. 我们将工业视频评估形式化为由五个场景领域和五个抽象任务类别构成的正交矩阵，覆盖 60 个场景族中的 500 个带标注任务。
2. 我们发布领域均衡的 500 任务集。每个任务拥有独立参考图、冻结的提示词规范、四级难度标注和明确的应用目标。
3. 我们提出一个可审计的“五加一”评测协议，将结构化多模态评分、确定性时间证据、任务感知计算机视觉算子、可观察事件检查以及不重复计算的硬性门控结合起来。
4. 我们评估十个具有代表性的视频生成系统，并报告排名、置信区间、领域—任务分解、难度趋势和失败分析。


## 2. 相关工作

### 2.1 视频生成评估

早期的分布式指标，例如 Fréchet Video Distance，通过比较真实视频和生成视频的特征分布来衡量生成质量，但单一的语料级统计值难以诊断提示词条件视频生成中的具体问题。

VBench 将视频生成质量拆分为多个感知和语义维度，并使用人类偏好验证各项指标；VBench++ 将这一框架进一步扩展到图生视频和可信性评估。EvalCrafter 使用大规模提示词集合和经人类意见校准的客观指标进行广泛评测。与这些工作不同，FORGE-Bench 专注于工业正确性，包括结构不变量、事件因果关系、物理演化、镜头执行情况以及下游决策价值。

### 2.2 组合能力与推理导向评估

T2V-CompBench 使用学习式指标和程序化指标测试属性、动作、交互、空间关系和数量组合能力。这类研究说明，仅依赖一般性的文本—视频相似度不足以评估复杂生成任务。

工业提示词往往还包含条件约束。例如，机器应当在人员越过安全边界之后停止；断裂必须局限在指定区域；载荷应当运动，而吊具与载荷必须保持耦合。因此，FORGE-Bench 为每个任务配置可观察事件、隐含规则问题、失败模式和任务特定证据。

### 2.3 多模态裁判与混合指标

大型多模态模型能够描述时间证据并应用自然语言评分准则，但它们的输出可能受到提示词措辞、视觉采样不完整和分数锚定效应的影响。纯程序化指标具有相反的局限：它们容易复现，但通常只能捕捉狭窄的代理信号。

我们的协议结合了两者。模型裁判负责给出语义维度分数；传统视觉算子则提供关节漂移、局部区域变化、烟羽连续性和镜头运动等测量证据。只有在适用性、有效性和置信度条件满足时，这些算子证据才会影响评分，并且绝不会被当作额外的独立评分维度重复计算。

### 2.4 工业视觉理解

工业视觉研究通常只针对某项具体下游任务，例如缺陷检测、机器人操作、安全监控或预测性维护。FORGE-Bench 则评估视频生成模型是否能够产生在这些工作流程中具有潜在用途的视频。

本基准并不宣称生成视频可以直接安全部署。它衡量的是：可见证据是否符合冻结的工业任务要求，以及这些要求在哪些方面未被满足。

## 3. 基准设计

### 3.1 设计目标

本基准遵循四项原则：

1. 每个样本都必须指定一个可观察事件，而不能只是风格要求。
2. 参考图像用于定义视觉身份以及应保持稳定的区域。
3. 每项任务的标注必须指出至少一种有意义的失败模式。
4. 评测既要支持单一标量比较，也要能够把问题定位到具体领域、任务族、评分维度或事件。

### 3.2 数据集组成

数据集包含来自 60 个场景族的 500 个样本和 500 张独立参考图像，每个领域恰好包含 100 个任务。

任务类别并非强制均匀分布，因为并非每种能力在每个领域中都同样合理。例如，流体行为在极端应急场景中非常常见，但在具身机器人任务中没有对应样本。

表 1 按场景域统计数据集组成：

| 场景域 | 样本数 |
|---|---:|
| 视觉安全 | 100 |
| 具身机器人 | 100 |
| 重载施工 | 100 |
| 精密缺陷生成 | 100 |
| 极端应急事件 | 100 |

表 2 按任务类别统计数据集组成：

| 任务类别 | 样本数 |
|---|---:|
| 刚体运动学与耦合 | 109 |
| 拓扑变化与失效 | 114 |
| 流体动力学与热力学 | 83 |
| 空间探索与视角运动 | 79 |
| 工业逻辑与合规性 | 115 |

### 3.3 场景领域

**视觉安全**涵盖入侵、个人防护装备、车辆—行人交互、监控视角和警报响应。

**具身机器人**涵盖操作、移动导航、接触、物品交接、安全联锁和紧急停止。

**重载施工**重点考察吊装系统、起重机和挖掘机运动学、地面支撑、对准过程与载荷路径失效。

**精密缺陷生成**针对 PCB、焊缝、齿轮、连接器、密封件和表面的局部缺陷，以及内窥镜检查。

**极端应急事件**涵盖压力释放、火灾、烟雾、热失控、结构倒塌、疏散和围护结构破坏。

### 3.4 任务分类体系

五个抽象任务类别将具体场景与底层能力分离。

- 刚体任务要求关节、支撑、接触关系和耦合运动保持稳定。
- 拓扑变化任务要求指定的局部结构发生变化，同时保持未受影响区域不变。
- 流体和热力学任务要求传播方向、连续性、扩散过程以及与边界的交互符合物理规律。
- 空间视角任务要求执行明确的环绕、平移、推拉、检查轨迹或静止镜头条件。
- 工业逻辑和合规任务要求完整呈现“触发—响应—结果”因果链。

这一分类形成了可解释的领域—任务矩阵。矩阵中的空单元格具有实际含义，而不是数据遗漏：它表示基准尚未为某个领域—能力组合定义足够合理、可辩护的任务。报告只统计有样本的矩阵单元，不会对空单元进行插值。

### 3.5 提示词与标注规范

每个运行样本包含一条简洁的 `video_generation_prompt` 和一条更丰富的评测提示词。

生成提示词规定：

- 可见事件；
- 镜头行为；
- 最终状态；
- 参考图保持要求；
- 禁止出现的伪影。

评测记录进一步包含：

- 硬约束；
- 必须可见的事件；
- 与决策相关的元素；
- 成功条件；
- 隐含规则问题；
- 各维度评分准则；
- 预期的误导性失败模式。

所有输出视频均使用 `{task_id}.mp4` 命名，使任务与模型输出之间的映射具有确定性。

### 3.6 难度分层

难度在模型评测之前完成分配。500 任务运行子集采用固定的 20/30/30/20 分布：

- 简单：100；
- 中等：150；
- 困难：150；
- 对抗：100。

难度综合考虑交互耦合、结构复杂度、视角运动范围、事件数量、遮挡、物理约束以及已知模型弱点。“简单”只是相对于本工业基准而言，仍然要求模型完成可观察事件并保持身份与时间一致性。

镜头运动分布如下：

- 静止镜头：182；
- 推拉镜头：119；
- 平移镜头：101；
- 环绕镜头：98。

应用目标分布如下：

- 应急演练：125；
- 重型作业风险评估：100；
- 机器人操作：100；
- 安全培训：84；
- 检查与维护：58；
- 缺陷生成：33。

## 4. 评测协议

### 4.1 五个技术维度与一个应用维度

对于样本 $i$，裁判模型输出五项技术得分 $s_{i,a}\in[0,100]$：

1. 工业逻辑与事实一致性；
2. 几何完整性；
3. 物理合理性；
4. 时间一致性；
5. 参考图像与运动保真度。

应用实用性 $u_i\in[0,100]$ 被单独评估，因为技术上看似合理的视频仍然可能无法服务于预期工作流程。

令 $w_{i,a}$ 表示由任务类别决定并归一化后的维度权重。技术分为：

$$
T_i=\sum_{a=1}^{5}w_{i,a}s_{i,a},\qquad \sum_{a=1}^{5}w_{i,a}=1.
$$

门控前的透明线性得分为：

$$
L_i=0.8T_i+0.2u_i.
$$

最终样本排名分 $R_i$ 对每项预先定义的正式门控最多应用一次：

$$
R_i=G(L_i;\mathcal{E}_i,\mathcal{O}_i),
$$

其中，$\mathcal{E}_i$ 表示事件和应用检查，$\mathcal{O}_i$ 表示通过有效性验证的算子证据。模型总排名使用所有必需维度完整样本的平均值，同时报告 bootstrap 置信区间和全样本线性诊断分。

### 4.2 时间证据与多模态评分

评测协议解码每一段有效视频，并保留原始帧率的视频帧供连续计算机视觉检查使用。多模态裁判接收确定性的 2 FPS 采样结果，采样保证覆盖首帧和末帧，并记录原始帧索引。

在 Qwen3-VL-235B 部署中，按时间排序的帧会被组合成一张带编号的证据板，以满足服务端“每个请求最多一张图像”的限制，同时不丢弃已采样的视觉证据。

裁判温度固定为 0，模型标识固定。每个维度均要求返回结构化 JSON，其中包含：

- 得分；
- 推理说明；
- 失败模式；
- 置信度；
- 证据帧索引。

### 4.3 算子证据

本评测使用五类视觉算子辅助裁判：

1. **局部区域锁定**：检查局部缺陷任务是否真的只改变指定区域，而不是重新生成整个场景。
2. **流体与烟羽连续性**：测量泄漏、烟雾、火焰、喷雾和压力释放的面积变化及中心轨迹连续性。
3. **刚性关节跟踪**：估计经过镜头运动补偿后的成对距离漂移和特征轨迹覆盖范围。
4. **安全响应运动**：在合规任务中提供停止或减速行为的弱证据。
5. **视角运动保真度**：测量环绕、平移、推拉及静止镜头要求是否被执行。

视觉算子只产生证据和风险标志。只有在适用性、有效性和置信度条件全部满足时，相关测量才可能限制对应维度的分数。这样可以避免重复计分，也可以防止不稳定的代理指标无条件决定最终结果。

### 4.4 应用与推理检查

应用实用性要求决策关键事件真实可见。例如，应急视频必须同时表现相关触发事件和响应，而不能只生成具有“危险氛围”的画面。

每个样本还可以包含二元隐含规则问题。这些问题的正确率构成推理一致性诊断指标，但不会取代五加一主分数。

### 4.5 有效性与可复现性

以下问题都会在报告中显式展示：

- 视频缺失；
- 视频无法解码；
- 裁判响应格式错误；
- 必需维度缺失；
- 是否使用分数下限。

这些问题绝不会被静默插值。若某个模型输出在评分前已经被拒绝，则会明确记录为 rejected，并继续保留在 500 任务的覆盖率分母中。

报告还保存样本清单、评分配置、评测代码和裁判配置的哈希值，并记录依赖库版本与采样元数据。

## 5. 实验

### 5.1 实验设置

我们评估十个图生视频系统。为避免仅使用厂商名称造成版本歧义，实验中使用的 MiniMax 基线明确记为其 API 模型标识 `MiniMax-Hailuo-2.3`；另一个独立视频集记为 `MiniMax H3`，不与该 API 基线混称：

- HunyuanVideo 1.5；
- HunyuanVideo 1.5 Distill；
- MiniMax Hailuo 2.3（API 模型标识：`MiniMax-Hailuo-2.3`）；
- MiniMax H3；
- Kling 3.0 Standard；
- Seedance 2.5；
- CogVideoX 1.5；
- Wan 2.1；
- Wan 2.2；
- Wan 3.0。

每个系统接收相同的 500 组参考图像与任务，以及冻结的生成提示词。视频通过任务 ID 映射，并由统一评测管线解码。

正式裁判模型为 Qwen3-VL-235B-A22B-Instruct-FP8，使用四卡张量并行部署，并采用四个确定性数据分片。

Seedance 2.5 包含 499 个有效视频；任务 `erob_190` 被明确记录为模型输出 rejected，并继续计入覆盖率统计。

分项结果揭示了平均排名之外的能力差异。MiniMax Hailuo 2.3 在几何完整性（62.638）、物理合理性（41.276）、时间一致性（64.939）以及参考图像与运动保真度（13.571）上均高于两种 HunyuanVideo 版本，并取得最高线性分 43.681；但其 500 个样本中有 51 个必需事件覆盖率为零，明显多于 HunyuanVideo 1.5 的 12 个和 Distill 的 15 个。零事件完成门控将这类样本的最终分限制为 0 后，MiniMax Hailuo 2.3 的最终排名分降至 26.280。最高分没有上升，三模型点估计极差由 0.271 扩大到 0.860。这说明较高的分项质量和线性平均分并不必然转化为更高的严格工业可用性排名。

### 5.3 分析框架

实验分析围绕三个问题展开：

1. 一般视觉连贯性是否足以保证较高的工业排名，以及时间质量相近的模型是否会在几何、物理或事件完成度上产生差异；
2. 性能如何随难度变化，以及对抗任务是否放大模型差距；
3. 不同模型在领域—任务单元中是否呈现能力权衡，以及单一平均分会掩盖哪些差异。

### 5.4 领域与任务分解

领域—任务分解采用 $5\times5$ 矩阵，并对所有非空单元计算宏平均分。

该分析可以判断，例如，某个模型的几何弱点是普遍存在，还是主要集中于周期性精密结构；也可以判断极端应急场景中的失败主要来自流体演化错误，还是来自因果链不完整。

### 5.5 难度与应用分解

结果将按四个预先指定的难度等级和六种应用类型分层。关键问题不只是分数是否随难度单调下降，而是哪一个评分维度最先成为瓶颈。

应用报告单独计算必需事件覆盖率和严格应用通过率，从而避免总体平均分掩盖关键事件缺失。

### 5.6 定性失败分析

定性分析关注传统视觉质量评价与 FORGE-Bench 结论明显不一致的案例，主要包括：

1. 画面平滑但实际静止，未执行指定镜头运动；
2. 视觉效果强烈但拓扑结构不可能成立；
3. 单帧看似合理，但跨帧身份或材料发生破坏；
4. 局部缺陷提示导致整个场景被重新生成；
5. 安全场景缺失触发事件、响应过程或最终状态。

案例分析结合参考图像、按时间排列的证据帧、各维度得分、门控原因以及裁判证据，定位视觉观感无法揭示的工业失效。

### 5.7 局限性

本基准规模有限，无法覆盖所有工业行业、地区标准和设备类型。部分物理属性仅凭像素无法可靠推断。即使采用确定性解码，多模态裁判仍可能存在偏差或不一致；证据板也会压缩部分时间信息。

运行子集按领域保持均衡，而不是按照现实部署频率采样。最后，基准得分只表示视频是否符合带标注的视觉任务要求，并不代表对安全性、工程正确性或法律合规性的认证。

## 6. 结论

本文提出 FORGE-Bench，一个面向工业图生视频任务的评测基准，将结构、物理、因果、时间和应用正确性与传统视觉质量放在同等重要的位置。

其领域—任务矩阵、500 任务运行子集、五加一评分结构、任务感知证据算子和明确的有效性报告，旨在使模型比较既可复现，又能够为模型改进提供具体方向。

本基准提出了一个比“视频看起来是否真实”更严格的问题：视频是否保持了正确结构、执行了所需事件和镜头行为、遵守可见的物理约束，并能够支持预期工业决策？

我们希望 FORGE-Bench 能够推动视频生成系统从“视觉上令人信服”进一步发展为“在高风险工业工作流研究中更可靠、更可审计”。
